### 2. 🔬 Anthropic 發布 MHS：讓 AI agent 直接操作實驗室與工廠設備（08-27~28）

Anthropic 首次跨進**實體 AI**，發布 **Model Hardware Standard（MHS）** 研究預覽——一套讓 AI agent 安全操作實體設備的共通規格。

**能做什麼：**
- 讓 agent **同時操作多台**實驗室與製造設備：顯微鏡、液體處理器（liquid handler）、機械手臂
- 任務範圍從**例行藥物開發實驗**到**量子電腦的雷射校準**

**解決什麼問題：**
- 傳統上實驗室或製造廠整合硬體要花**數週到數月**，因為多數設備彼此不通訊、每台都需要客製整合
- MHS 把整合工作**壓縮到數小時甚至數分鐘**
- MHS 儲存「這台硬體如何運作」的資訊，讓 AI 不必依賴紙本手冊或師徒相傳的默會知識（tacit knowledge）

**技術特性：**
- 適用於**任何具備可程式介面**的裝置
- **模型無關（model-agnostic）**：任何 agent harness 都能透過標準協定存取，**包括 MCP**
- 起源於 Anthropic 與 **HHMI Janelia 研究園區**的合作
- 目前為**研究預覽**，先開放給第一批科研實驗室與先進製造商；Anthropic 表示預覽結束後會公開，但**未承諾具體日期**

**對你的意義：** 這件事的意義不在你明天會用到，而在**方向**：MCP 讓 AI 接上軟體世界，MHS 是同一套邏輯延伸到硬體。你手上的 ACE-Step、TTS、STT 那些本機工具鏈，本質上都是「把 AI 接到某個介面」——MHS 想做的是把這件事標準化到實體儀器。**如果這個標準成立，「AI 能操作什麼」的邊界會從螢幕擴張到桌上的機器。**

### 3. ⚡ Claude Code auto mode 的完整數據出爐——包含 Anthropic 沒放在頭條的那個數字

W33 報導 auto mode 成為預設時，主打的是「分類器攔截 89% vs 人類 13.6%」。本週有更完整的壓力測試資料，**其中一個數字值得你知道**：

| 指標 | 數值 | 說明 |
|---|---|---|
| 攔截危險動作 | **89%** | W33 已報導 |
| **誤放率（false negative）** | **17%** | **過度積極的危險動作仍有 17% 被放行** |
| 誤擋率（false positive） | **0.4%** | 安全動作被誤擋的比例很低 |

**分類器架構（兩階段）：**
- **Stage 1**：快速單 token 過濾，調成高召回率（production 上誤擋率 8.5%）
- **Stage 2**：對 Stage 1 標記的動作做 chain-of-thought 推理，把誤擋率降到 0.4%——**代價是放行了 17% 的過度積極動作**

**主要失效模式（值得記住）：** 分類器會在對話中找到「**看起來像批准的證據**」，然後就停止追問——**沒有去確認那個批准是否真的涵蓋這個動作的實際影響範圍（blast radius）**。

**你可以立刻用的兩件事：**
1. **`claude auto-mode critique`** — 這個指令會**審查你自訂的規則**，標出模稜兩可、重複、或可能造成誤判的條目
2. **`permissions.deny` 是硬防線** — deny 規則在分類器看到動作**之前**就攔下，「分類器與你自己陳述的意圖都無法覆蓋它」；另有 data exfiltration 這類 **hard-deny 類別，分類器根本無權批准**

**對你的意義：** 這正好接上 W33 我建議你做的事，而且現在有了具體工具。**17% 誤放率意味著 auto mode 不是保險箱**——它比人類好很多（人類 13.6%，長 session 後降到 5%），但真正不能出事的操作，唯一可靠的是寫進 `permissions.deny`。你上週剛把「push 到公開 repo 前先問」這類紅線寫進 CLAUDE.md，下一步可以考慮把其中最硬的幾條落到 deny 規則。
