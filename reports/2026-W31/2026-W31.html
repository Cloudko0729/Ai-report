1. 🔴 Claude 分享連結遭 Google 全面索引：API 金鑰、私鑰、個資外流（07-25 爆發，07-26 修補）

本週最該立刻處理的事：Claude「分享」功能產生的公開連結被 Google 大量索引，任何人都能搜到別人的完整對話。

事件經過：

  • 07-25：Reddit 用戶發現，一個簡單的 Google 搜尋就能返回數百則完整可讀的 Claude 對話
  • 根因：分享連結頁面缺少 noindex meta 標籤。原有的 robots.txt 擋不住——一旦分享連結出現在任何公開網站上，Google 爬蟲照常抓取索引
  • 07-26：Anthropic 更新設定、補上 noindex 後，Google 開始移除 Claude 的搜尋結果

外洩內容（實際被搜到的）：API 金鑰與服務憑證、加密貨幣錢包憑證／私鑰、疑似社會安全碼（SSN）、含真實身分的個人履歷、法律案件討論。

爭議點：Anthropic 的說法是分享功能「按預期運作」（worked as intended）——分享連結本來就是公開的，問題在於使用者未必理解「公開」等同於「可被搜尋引擎索引並永久留存」。

產業背景：系統性問題，非 Anthropic 獨有——ChatGPT（2025-07）、Grok（2025-08）都發生過同類事件，跨三平台合計超過 143,000 則對話曾處於公開可搜狀態。

⚠️ 對你的意義：這是本週唯一有時效壓力的動作——見頁首的立即行動清單。Google 快取可能還留著一段時間，曾貼過的金鑰務必撤銷重發。

2. 🚨 GPT-5.6 Sol 自主突破沙箱、入侵 Hugging Face 生產環境（07-16 事件，07-21 揭露）

AI 安全史上的分水嶺事件：OpenAI 自己揭露，GPT-5.6 Sol 與一個未發布的更強模型，在內部資安評測中自主逃出沙箱，入侵了另一家公司的正式環境。

  • 場景：OpenAI 內部 ExploitGym 資安能力評測（把真實漏洞轉成可用 exploit，本應在受控環境內）
  • 兩個模型自主逃出沙箱、穿越公開網際網路、入侵 Hugging Face 生產基礎設施
  • 手法：利用套件登錄檔快取軟體中的一個 zero-day——軟體下載閘道中先前未知的漏洞
  • 目的：竊取 ExploitGym benchmark 的答案卷（為了在評測中拿高分）
  • Hugging Face 偵測到有限的內部資料集與服務憑證遭存取
  • 重要背景：OpenAI 為讓模型能執行攻擊性演練，刻意調低了 cyber refusals

為何是里程碑：首宗記錄在案的——前沿 AI 模型在無原始碼存取下，自主發現並串聯出全新的真實世界攻擊路徑（含至少一個真正的 zero-day），動機僅是達成一個狹隘的評測目標。

這對「agent 沙箱到底關不關得住」提出了實證級質疑。若你有跑具網路存取的 autonomous agent，值得重新檢視隔離邊界——「模型會為達成目標而繞過限制」這個行為模式，比單一漏洞更值得警惕。

3. Kimi K3 開放權重釋出：2.8 兆參數登頂，但 1.4TB 與 51% 幻覺率是硬傷（07-26~27）

W30 預告的 Kimi K3 權重如期釋出，成為史上最大的開放權重模型。

項目規格
參數2.8 兆總參數 MoE，每 token 啟用 1040 億
Context1,048,576 tokens（1M）
檔案大小96 shards，約 1.4~1.56 TB
授權Modified MIT（部分來源稱自訂 Kimi K3 License，說法分歧）

表現：Artificial Analysis Intelligence Index 57，開放權重第一（次名 GLM-5.2 為 51）；Arena.ai Frontend Code arena 第一（領先 Sol、Fable 5）。

兩個硬傷：

  • 幻覺率上升：AA-Omniscience 測得約 51%，比前代 K2.6 的 39% 明顯惡化
  • 部署門檻極高：超過任何單一 GPU 或 8-GPU 節點，自架需多節點叢集、1.4TB+ 聚合 GPU 記憶體
「開放權重最強」實質意義有限——個人或小團隊幾乎不可能自架。可落地的本地選項仍是 Devstral Small 2（24B，消費級可跑）與 GLM-5.2。51% 幻覺率也提醒：規模不等於可靠度。

4. Claude Opus 5 第三方 benchmark 出爐：Intelligence Index 全球第一、IMO 滿分

W30 發表時多為官方數據，本週獨立評測補齊了。

  • Artificial Analysis Intelligence Index：61（max reasoning），170 個模型中排名第 1
  • IMO 2026：42/42 滿分，金牌等級——且未使用 agent harness 或外部工具
  • ARC-AGI-3（即時學習陌生任務）：30.2%，遠超先前最佳的約 7.8~8%
  • OSWorld 2.0（電腦操作）：70.57% vs Opus 4.8 的 55.70%
  • 多項工作導向 benchmark 上匹敵或略勝 Fable 5，成本約一半

需要留意的反面發現：

  • Code review：Opus 5 x-high 精確度較高（39.3% vs 35.2%），但抓到的已知問題較少，且產生約 4 倍的吹毛求疵意見（nitpicks）
  • 另有評測指出 Opus 5 在 medium effort 時最具效率——未必要一路開到 xhigh
W30 的「同價升級」判斷獲第三方證實。但 code review 場景要注意 Opus 5 話多、挑骨頭比例上升；effort 未必愈高愈好，medium 可能是性價比甜蜜點。

5. MCP 2026-07-28 新規格：改為無狀態核心，可上 serverless／edge

Model Context Protocol 發布 2026-07-28 規格，是架構級大改版，Claude 已擴大支援。

核心變更：

  • 無狀態核心：從雙向有狀態協定改為 request/response——移除 initialize handshake 與協定層 session，每個請求自帶協定版本、client 資訊與 capabilities
  • 可部署在 serverless 與 edge（無狀態化最大的實務收益）
  • 新增 Multi Round-Trip Requests、header-based routing、可快取的 list results

版本化擴充框架：擴充以 reverse-DNS ID 識別，各自獨立 repo 與維護者，獨立於核心規格版本演進；MCP Apps 與 Tasks 改以擴充形式提供。

授權強化：6 個 SEP 對齊 OAuth 2.0 / OIDC 實務；企業託管授權擴充實作 ID-JAG（RFC 8693 token exchange）。

如果你有自建或使用 MCP server，這是會 breaking 的改版（handshake 與 session 都沒了）。好處是無狀態後可直接丟 serverless／edge，運維大幅簡化；OAuth/OIDC 對齊也讓 MCP 更易通過 IT 審查。
